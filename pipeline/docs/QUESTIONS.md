## 計画書 3.4 の項目

1. **CSV の列名・区切り・ヘッダー・ファイル分割** → 回答：カンマ区切り・ヘッダーあり。GPS と加速度は別ファイル（`accel.csv` / `gps.csv`）。詳細は `docs/data_schema.md` 2.
2. **加速度の実サンプリング周波数** → 回答：**約 398.5 Hz**（走行ごとに 397.5〜400.2 Hz。設定 400 Hz）。計画書の推定 50〜200 Hz より高く、帯域特徴量（9.4）が実装できる。
3. **加速度の単位と重力** → 回答：**g、重力込み**（静止時の合成加速度 ≈ 0.95〜0.97 g）。
4. **測定レンジと ODR** → 回答：**±16 g フル分解能（3.9 mg/LSB）、ODR 400 Hz**（スケッチ `DATA_FORMAT=0x0B`、`BW_RATE=0x0C`）。郊外走行（ride_007）で X 軸が 15.9 g に 1 回達している。
5. **時刻列の種類** → 回答：全列 ESP32 の `esp_timer`（起動からの us）。GPS の `utc`/`date` を `t_rx_us` で対応付けて絶対時刻にする。GPS 未捕捉時は相対時間のみ（絶対時刻は NaN）。
6. **fix 状態・衛星数・HDOP** → 回答：**記録されている**（`status`, `fix`, `sats`, `hdop`）。計画書フェーズ 5 の「fix 状態の記録」は **すでに実装済み**。
7. **GPS 更新周期と速度列** → 回答：1 Hz、RMC の対地速度を km/h に変換済みの `speed_kmh` あり。
8. **郊外走行で GPS が取れなかった原因** → 部分回答：ride_006〜009 は先頭から最後まで衛星 0 で、**時刻すら受信していない**。直前の ride_001〜005 は 4〜38 秒で測位できているので、コールドスタートではなく受信自体の問題（アンテナ遮蔽か GPS TX 線の接触）が濃厚。
   - **質問 8-a**：ride_006 以降でロガーの置き場所・向き・カバーの有無を変えましたか（ride_008/009 は重力の向きが変わっています）。GPS のアンテナが金属や体で覆われていませんでしたか。
   - **質問 8-b**：ride_006〜009 の内容（いつ・どこを走ったか）と、ride_006・ride_008 が何だったか（短いので停車中か試験か）を教えてください。
9. **自宅の座標** → **質問 9**：公開出力（地図）でマスクするために自宅の緯度・経度（10 進の度）が必要です。`config/local.yaml`（コミットしない）に `home: {lat: …, lon: …}` の形で書いてください。歯医者側もマスクするなら同じ形で追加してください。代替案：ride_004 の最初の有効 fix を自宅とみなして自動設定（確認が要るので、まずは質問）。

## 方針として決めたこと（確認不要、異議があれば教えてください）

- GPS の品質フィルタ：`status=="A"` かつ `sats ≥ 5` かつ `hdop ≤ 5` の行だけを使う。
- 停止判定：`speed_kmh < 5`。
- 帯域特徴量（計画書 9.4）は fs ≈ 398 Hz なので実装する（ナイキスト 199 Hz）。
- 位置情報の実値（緯度・経度）はノートブック出力・ドキュメント・コミットに含めない。軌跡は最初の fix からの相対距離（m）で描く。地図タイルは folium（OpenStreetMap）で、ブラウザがタイルを取る際にタイル座標がタイルサーバーに送られる点は静的 HTML でも避けられない（マスク済みの範囲だけを描く）。
